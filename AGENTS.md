## GC 

Terms:

Gc type: any type that's a pointer than object of a `class` or `slice` type. (interface, coroutine types are also GC types because they are technically class types)
Inline type: inline structs: <MyType> or fixed arrays: [MyType x 10] or any type that consists of multiple fields grouped together and are copied by value and live on the stack (or inline in another object/fixed-array/...) e.g. closure type, tagged null type, union type, etc...
Nullable type: either a pointer type that can be `null`, or a tagged type with `is_present` tag for non-pointers

How it works:

The GC tracks gc type pointers including nullable gc pointers

Gc type objects are allocated by the pool allocators
Non gc type objects are allocated by mem:alloc

Each gc type has its own allocator (generator) with their own property marking function (generated)

A marking function extracts all the gc type pointers from that object's properties non-recursively.
However, it does extract gc pointers from properties with inline types recursively. because those properties technically also belong to that object.
If the type of the object that's being marked has a `_props` function, then this must also be called inside our marking function.
Raw pointers & ref pointers are ignored regardless if their offset typehint refers to a type that is or contains a gc type.

The compiler also generates a marking function for each stack-frame that contains gc pointers.
At the start of the function we push the address of that function on the gc stack + the address of the previous frame
We then increase the stack pointer by (frame size + size of 2 pointers)
The frame size is the sum of all type sizes of each decl/var type that is or contains a GC pointer. Each gc typed decl points to an offset inside this frame that matches with the generated mark function.

The marking functions for both the frames & allocators are generated by the same function in the compiler.
